# gijiroku-jp: 議事録の作成と点検

議事録の読み手が知りたいのは「**何が決まったか／誰がいつまでに何をするか**」。
発言の書き起こしではなく、決定事項とToDoを先頭に置く。

## 入力
- 会議のメモ、チャットの抜粋、文字起こし（話者名つきでもなしでもよい）
- 足りなければまとめて聞く：会議名、日時、参加者、ToDoの担当と期限
- **推測で担当や期限を決めない**。メモにない担当・期限は【要確認】と書く。

## 手順
1. 入力から「決まったこと」「やること」「決まらなかったこと（持ち越し）」を分ける。
2. 下の形式で議事録を書く。決定事項とToDoを先に、経緯は短く後に置く。
3. 次のスクリプトでToDo表を点検する。
   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/check_minutes.py minutes.md
   ```
   担当・期限の抜けや「早めに」「なるべく」のようなあいまいな期限が指摘されたら、【要確認】にするか、ユーザーに確認する。
4. 指摘が0件になったら（または【要確認】として残したら）出力する。

## 形式

```markdown
# 【会議名】 議事録

- 日時：【YYYY/MM/DD HH:MM〜HH:MM】
- 参加者：【氏名（所属）、…】
- 記録：【氏名】

## 決定事項
1. 【決まったことを1文で。主語と対象を明確に】

## ToDo
| # | 内容 | 担当 | 期限 |
|---|---|---|---|
| 1 | 【具体的な作業】 | 【氏名】 | 【MM/DD】 |

## 持ち越し・未決事項
- 【決まらなかったこと／次回までに確認すること】

## 議論の要点
- 【論点】：【主な意見と結論に至った理由を1〜2文】

## 次回
- 【日時・議題（決まっていれば）】
```

## ルール
- 決定事項は「〜する」「〜に決定」と言い切る。議論中の案は持ち越しに入れる。
- ToDoの内容は動詞で終える（例：「見積書を再提出する」）。「検討」だけの項目は、何をどう検討するかを書く。
- 期限は日付で書く。「来週中」は具体的な日付に直す（会議日から計算し、曜日も添える）。不明なら【要確認】。
- 発言者の個人的な評価や雑談は記録しない。必要なら要点だけ。
- 社外秘・個人情報（口座番号、健康情報など）がメモに含まれていたら、記録してよいか確認する。
