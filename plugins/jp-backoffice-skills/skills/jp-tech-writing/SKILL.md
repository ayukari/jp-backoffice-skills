# jp-tech-writing: 日本語技術文書の校正

## 手順
1. まず機械チェックをかける（コードブロックとインラインコードは対象外）。
   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/jp_style_lint.py doc.md
   ```
2. 指摘を種類ごとにまとめ、修正案を示す。機械チェックは目安なので、文脈で判断して不要な指摘は捨てる。
3. 機械では拾えない点を人の目で確認する（下の「読み手目線のチェック」）。
4. 修正版を出力する。変更点は「前 → 後」の表で示す。

## 機械チェックの内容
| ルール | 何を見るか | 直し方 |
|---|---|---|
| `long-sentence` | 100文字を超える文 | 2文に分ける。条件と結果を分ける |
| `many-commas` | 読点が4つ以上の文 | 箇条書きにする／文を分ける |
| `mixed-style` | です・ます調と、だ・である調の混在 | 文書全体でどちらかに統一（READMEや記事はです・ます調が無難） |
| `redundant` | することができる、を行う、となっております など | より短い表現に置き換える |
| `hyogen-yure` | サーバー/サーバ、ユーザー/ユーザ、全て/すべて、GitHub表記 など | 文書内で1つに統一する |
| `double-ga` | 1つの節に「が」が2回 | 「〜は」に変える、語順を変える |

## 読み手目線のチェック
- **最初の3行で「何ができるか」が分かるか。** READMEは冒頭に一文の説明、次にインストール、次に使い方。
- **手順は番号付きで、1ステップ1操作か。** 期待される結果（「〜と表示されれば成功」）を書く。
- **用語を初出で説明しているか。** 略語は初出で正式名称を併記する。
- **主語と対象がはっきりしているか。** 「設定します」→「`config.yaml` の `timeout` を 30 に設定します」。
- **コード・コマンドはコードブロックか。** コピーして動く形にする。

## 表記の基本方針（指定がない場合）
- カタカナ長音：「サーバー」「ユーザー」（JIS Z 8301 / 内閣告示の慣用に合わせて長音あり）
- 補助動詞・形式名詞はひらがな：「〜してください」「〜できる」「〜こと」「〜とき」
- 英字の固有名詞は正式表記：GitHub、JavaScript、TypeScript、macOS
- 全角と半角の間のスペースは、文書内でどちらかに統一する
