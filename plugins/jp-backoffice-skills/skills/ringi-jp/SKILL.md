# ringi-jp: 稟議書の作成と添削

稟議書の目的は、決裁者が**この書類だけで「承認してよいか」を判断できる**ようにすること。
結論を先に書き、費用・効果・リスクを数字で示す。

## まず集める情報
足りないものだけまとめて質問する。推測で数字を作らない。

| 項目 | 例 |
|---|---|
| 件名（何を決裁してほしいか） | 〇〇ツール導入の件 |
| 申請者・部署・申請日 | 営業部 山田 2026-10-05 |
| 決裁希望日と理由 | 10/20まで（11月の繁忙期前に稼働させたいため） |
| 内容（何を・いくつ・いつから） | 〇〇を10ライセンス、11月から |
| 費用（初期・月額・年額、税込/税抜） | 初期0円、月額1,100円×10＝11,000円（税込） |
| 目的・背景（いまの課題） | 手作業の集計に月20時間かかっている |
| 効果（できれば数字で） | 月15時間削減 ≒ 人件費換算で月〇円 |
| 比較した選択肢 | A社・B社・現状維持 |
| リスクと対策 | 情報漏えい → SSO・権限設定で対応 |
| 予算の出どころ | 部門予算（IT関連費）から |

## 構成（この順で書く）

```markdown
# 稟議書：【件名】

| 申請日 | 【YYYY年M月D日】 | 申請者 | 【部署】【氏名】 |
|---|---|---|---|
| 決裁希望日 | 【YYYY年M月D日】 | 金額 | 【総額】円（【税込/税抜】） |

## 1. 申請内容（結論）
【何を、いくらで、いつから実施したいか。1〜2文】

## 2. 目的・背景
【現状の課題を数字で。なぜ今なのか】

## 3. 費用
| 項目 | 金額 | 備考 |
|---|---:|---|
| 初期費用 | 【】 | |
| 月額費用 | 【】 | |
| 年間合計 | 【】 | |

## 4. 期待される効果
【定量効果（時間・金額）と定性効果。費用対効果や回収期間】

## 5. 比較検討
| 案 | 費用 | 長所 | 短所 |
|---|---:|---|---|
| 【提案案】 | | | |
| 【代替案】 | | | |
| 現状維持 | 0 | | 【課題が残る】 |

## 6. リスクと対策
| リスク | 対策 |
|---|---|
| 【】 | 【】 |

## 7. スケジュール
【決裁後〜稼働までの流れ】

## 8. 添付資料
【見積書、比較表、カタログなど】
```

## 書き方のルール
- 1章で結論を言い切る。「〜を検討したい」ではなく「〜を導入したい（承認をお願いします）」。
- 費用は**税込か税抜かを必ず明記**し、月額は年額にも換算する。
- 効果は可能な限り数字（時間、件数、金額）で。数字がない場合は「定性効果」と明記し、測り方を書く。
- 比較検討に「現状維持」を必ず入れる（何もしない場合のコストを示す）。
- リスクを隠さない。リスクと対策がセットで書かれていると承認されやすい。
- 敬語は簡潔に（です・ます調）。社内文書なので過剰な謙譲表現は不要。

## 添削モード
既存の稟議書を受け取ったら、次の観点で「OK／要修正」の表を作り、修正案を示す。
1. 1章だけで何を承認すればよいか分かるか
2. 金額・税込/税抜・期間が明確か
3. 効果に数字があるか、根拠は妥当か
4. 比較検討（現状維持を含む）があるか
5. リスクと対策が対になっているか
6. 決裁希望日とその理由があるか
