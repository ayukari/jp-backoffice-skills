# nippo-jp: 日報・週報の作成

報告書の読み手が知りたいのは「**予定どおりか／何か手助けが必要か**」。
作業の羅列ではなく、結論・成果・課題・次の予定を短く書く。

## 入力
- 箇条書きのメモ、チャットの抜粋、`git log --since=yesterday --oneline`、カレンダーの予定など、形式は問わない
- 足りなければ聞く：対象期間、読み手（上司／チーム／顧客）、所定のフォーマットの有無

## 日報の形式

```markdown
## 日報 【YYYY/MM/DD（曜）】 【氏名】

**ひとこと:** 【今日の状況を1文で。例：見積作成は予定どおり、A社対応で1件相談あり】

### 今日やったこと
- 【成果が分かる書き方。例：A社見積書を作成し送付（〜10/7回答予定）】
- 【】

### 課題・相談
- 【困っていること／判断がほしいこと。なければ「なし」】

### 明日の予定
- 【】

### 所感（任意）
【気づき・改善案を1〜2文】
```

## 週報の形式

```markdown
## 週報 【MM/DD〜MM/DD】 【氏名】

### 今週のサマリー
【3行以内：進捗の全体像、予定との差】

### 主な成果
| 項目 | 状況 | 補足 |
|---|---|---|
| 【案件・タスク】 | 完了／進行中（〇%）／遅延 | 【数字や次の節目】 |

### 課題・リスク
- 【内容】 → 【対応案／必要な支援】

### 来週の予定
- 【優先度順に】

### 数字（任意）
【件数・売上・工数など、チームで追っている指標】
```

## 書き方のルール
1. **「ひとこと」/サマリーを最初に書く。** 読み手はここだけ読んで判断することが多い。
2. **作業でなく成果で書く。** ×「A社対応」→ ○「A社の見積書を送付、10/7回答予定」。
3. **数字・期日を入れる。** 「だいたい終わった」ではなく「8割完了、残りは10/8まで」。
4. **課題は対応案とセット。** 「〜で困っている。〇〇していただけると助かります」。
5. **社内向けは簡潔な丁寧語。** 過剰な謙譲語や前置きは不要。
6. **入力にない事実を足さない。** 推測した部分は【要確認】と書いて残す。

## 要約モード
1週間分の日報から週報を作るときは：
- 同じ案件の記録を1行にまとめ、最新の状況だけを書く
- 日報で繰り返し出てきた課題を「課題・リスク」に上げる
- 完了したものと継続中のものを分ける
